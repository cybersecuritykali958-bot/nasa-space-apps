# NASA Space Apps Challenge — роли команды (5 человек)

## Распределение

| # | Роль | Кто | Основной инструмент |
|---|------|-----|---------------------|
| 1 | Тимлид / продукт | _имя_ | Claude Code |
| 2 | Данные / Python | _имя_ | Claude Code |
| 3 | Фронтенд | _имя_ | Cursor |
| 4 | Бэкенд / интеграции | _имя_ | Claude Code или Cursor |
| 5 | Дизайн и презентация | _имя_ | Figma / Canva |

---

## 1. Тимлид / продукт
- Выбирает челлендж, формулирует идею одним предложением.
- Пишет `CLAUDE.md`, поднимает репозиторий, каркас Next.js, первый деплой.
- Определяет контракт данных (формат JSON) и раздаёт всем.
- Принимает мержи в `main`, решает спорные вопросы.
- Ведёт демо-сценарий на 2 минуты, выступает с питчем.

## 2. Данные / Python
- Находит и скачивает датасеты NASA (`earthaccess`, GIBS, FIRMS, POWER и др.).
- Обрабатывает (`pandas`, `xarray`, `rasterio`), сохраняет готовые JSON/GeoJSON в `/data`.
- Пишет перезапускаемые скрипты, описывает формат файлов.
- В первые часы отдаёт 2–3 маленьких тестовых файла, чтобы остальные не ждали.

## 3. Фронтенд
- Страницы, карта или глобус (MapLibre / Cesium / Globe.gl), графики.
- Сначала работает на моках по контракту данных, потом подключает реальные.
- Адаптивность и скорость загрузки, чтобы демо не тормозило.

## 4. Бэкенд / интеграции
- API (роуты Next.js или FastAPI), которые отдают данные фронтенду.
- База или хранилище (Supabase), если нужны.
- ИИ-функция: Claude API объясняет данные простым языком.
- Деплой, переменные окружения, кэширование (демо не должно зависеть от живых API NASA).

## 5. Дизайн и презентация
- UI-кит: цвета, шрифты, логотип, иконки.
- Макеты ключевых экранов для фронтенда в первые 4–6 часов.
- Слайды, текст питча, демо-видео, описание проекта для подачи.
- Скриншоты и сторителлинг: какую проблему решаем и при чём тут данные NASA.

---

## Кто с кем работает тесно
- Данные + бэкенд: форматы и эндпоинты.
- Фронтенд + дизайн: макеты и компоненты.
- Тимлид + дизайн: питч и демо-сценарий.

## Правила работы
- Один репозиторий, у каждого своя ветка, мерж в `main` каждые 1–2 часа.
- Папки: `/data`, `/web`, `/api`, `/docs`. Каждый правит только свою.
- Перед крупной задачей агента — коммит.
- Деплой с первого часа.
- Синхронизация на 5 минут каждые 4–6 часов.

## План на 48 часов
- **0–4 ч:** выбор челленджа, идея, контракт данных, каркас, деплой пустой страницы.
- **4–24 ч:** данные, UI на моках и API идут параллельно.
- **24–36 ч:** интеграция, демо-сценарий.
- **36–44 ч:** полировка, багфиксы, презентация, видео.
- **Последние 4 ч:** только мелкие правки, без новых фич.
