|-------|------|------|

## Стек
- **Фронтенд:** Next.js, TypeScript, Tailwind CSS, shadcn/ui.
- **Карты и 3D:** MapLibre или Leaflet (слои NASA GIBS), CesiumJS или Globe.gl, Three.js при необходимости.
- **Графики:** Recharts или deck.gl.
- **Бэкенд:** роуты Next.js для простого, FastAPI (Python) для тяжёлой обработки данных.
- **Данные:** `earthaccess`, `pandas`, `xarray`, `rasterio`.
- **БД / авторизация (если нужны):** Supabase.
- **ИИ:** Claude API для объяснения данных простым языком.
- **Деплой:** Vercel (фронтенд), Render или Railway (Python).

## Источники данных NASA
- Брать только те ресурсы, которые указаны в описании выбранного челленджа, и дополнять открытыми API NASA (Earthdata, GIBS/Worldview, FIRMS, POWER, Exoplanet Archive и т.д.).
- **Не зависеть от живых API во время демо.** Данные заранее обрабатываются и сохраняются в `/data` как JSON или GeoJSON, приложение читает их оттуда.
- Для каждого набора данных в `/data/README.md` указывать: источник, дату загрузки, формат и поля.

## Контракт данных
- Формат обмена между данными, бэкендом и фронтендом — JSON/GeoJSON.
- Описание полей хранится в `/data/README.md`. Менять формат можно только по согласованию с тимлидом.
- Фронтенд сначала работает на моках в `/web/mocks`, затем переключается на реальные данные.

## Правила кода
- TypeScript в строгом режиме, без `any` без причины.
- Python: типы, `ruff` для форматирования, скрипты запускаются повторно без побочных эффектов.
- Имена переменных и функций — на английском. Комментарии и тексты интерфейса — как решит команда.
- Маленькие компоненты и функции. Никакого дублирования кода, если можно вынести общую часть.
- Секреты и ключи только в `.env`, который не коммитится. Пример — в `.env.example`.
- Не добавлять новые зависимости без необходимости.

## Работа с git
- Своя ветка на человека: `feat/<имя>-<задача>`. Прямых коммитов в `main` нет.
- Мелкие коммиты, понятные сообщения.
- Перед любой крупной правкой — коммит, чтобы можно было откатиться.
- Мерж в `main` каждые 1–2 часа, принимает тимлид.

## Как работать агенту
- Перед изменениями прочитай нужные файлы и пойми существующую структуру.
- Делай то, о чём просят, без лишнего рефакторинга и «улучшений».
- Не трогай файлы чужих зон и общие конфиги без явной просьбы.
- Если задача неясна или затрагивает контракт данных, сначала задай вопрос.
- После изменений запусти сборку или тесты и убедись, что ничего не сломалось.
- Кратко опиши, что сделано и что осталось.

## Команды
- Установка зависимостей: `npm install` (в `/web`), `pip install -r requirements.txt` (в `/data` и `/api`).
- Запуск фронтенда: `npm run dev` (в `/web`).
- Запуск бэкенда: `uvicorn main:app --reload` (в `/api`), если используется FastAPI.
- Обновление данных: `python scripts/build_data.py` (в `/data`).
- _Обновить этот раздел, когда команды изменятся._

## План на 48 часов
- **0–4 ч:** выбор челленджа, идея, контракт данных, каркас, деплой пустой страницы.
- **4–24 ч:** данные, интерфейс на моках и API идут параллельно.
- **24–36 ч:** интеграция и демо-сценарий.
- **36–44 ч:** полировка, багфиксы, презентация, демо-видео.
- **Последние 4 ч:** только мелкие правки, без новых функций.

## Чего избегать
- Новых функций в последние часы.
- Зависимости демо от внешних сервисов, которые могут упасть.
- Правок в чужих папках без согласования.
- Больших изменений без коммита перед ними.
